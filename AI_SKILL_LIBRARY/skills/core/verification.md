# Skill: verification

Before claiming completion:

1. Re-read the requested outcome and acceptance criteria.
2. Run the strongest available automated verification for changed behavior.
3. Verify generated files/actions actually exist and are on the intended branch/runtime.
4. For current-data tasks, verify timestamp/source freshness.
5. For deployments, distinguish source commit from deployed runtime and verify runtime revision when possible.
6. Report any skipped or unavailable verification explicitly.

Evidence precedes success claims.
