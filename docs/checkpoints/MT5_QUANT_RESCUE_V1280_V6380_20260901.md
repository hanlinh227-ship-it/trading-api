## FAILURE MODE THAT THIS VERSION FIXES

The earlier XAU failure path was:

`profit not banked -> reversal -> old core loses -> hedge opens -> rebound -> hedge also loses -> rescue adds more -> gross exposure expands -> margin pressure/liquidation risk`

V63.80/V12.80 changes the repair architecture so rescue is not allowed to create a new problem while trying to heal the old one.

## LOCKED ARCHITECTURE

Execution priority remains centered on keeping useful profit during recovery:

`profit lock / basket trail -> winner harvest -> net-positive unwind -> reserve-funded target-aware loser healing -> ticket invalidation cut -> bounded confirmed dual-loss rescue -> rolling single-layer hedge -> continuous quantitative core rebalance`

### 1. NO OPPOSITE-CORE RESCUE

Dual-loss rescue is a CORE action and may NOT open a second CORE opposite an existing CORE. If the quant target reverses against surviving core inventory, the system must first use ticket-level reduction/healing and rolling hedge rather than constructing core-vs-core lock inventory.

### 2. RESCUE REQUIRES FRESH QUANT CONFIRMATION

This confirmation applies to rescue only; normal continuous quant participation is not globally paused.

XAU V63.80:
- minimum absolute Q: `0.50`
- minimum factor agreement: `0.64`

BTC V12.80:
- minimum absolute Q: `0.40`
- minimum factor agreement: `0.56`

### 3. TARGET-AWARE RESERVE HEALING

Reserve-funded loser reduction may only close a losing ticket if closing that ticket moves current net exposure toward the CURRENT quantitative target.

Close volume is capped by all of:
- losing ticket remaining volume;
- current live target gap;
- configured unwind action size;
- available realized healing reserve after safety buffer.

This prevents `cut -> overshoot target -> rebalance back -> cut again` churn.

### 4. TICKET INTELLIGENCE IS PRESERVED

Individual losing tickets continue to be evaluated by:
- target correction direction;
- loss per lot;
- adverse M15 ATR distance;
- ticket age;
- core versus hedge role;
- whether a hedge is still required.

Old managed/legacy orders remain part of the managed book through the existing ownership/adoption logic.

### 5. TOTAL TARGET SCALE-UP IS NOW SUBLINEAR

The previous V63.70/V12.70 action shard scale was sublinear, but `EquityAnchorFullLot()` still grew approximately linearly with equity. V63.80/V12.80 fixes this so the total equity-anchor target uses the same sublinear exponent as action sizing.

Existing exponent profile remains:
- XAU exponent: `0.72`
- BTC exponent: `0.78`

This is intended to grow account capacity as equity grows without allowing one bad sequence to scale gross exposure at the same speed.

## PROFIT DURING RECOVERY

The EA can continue realizing valid winner tickets while it is healing a losing book because winner harvest and net-positive unwind have priority before loss realization/rescue. Realized winner profit can feed the deferred healing reserve.

This architecture improves the probability that recovery is funded by actual realized gains rather than only by adding gross exposure. It does NOT mathematically guarantee that every recovery remains profitable or that liquidation can never occur.
