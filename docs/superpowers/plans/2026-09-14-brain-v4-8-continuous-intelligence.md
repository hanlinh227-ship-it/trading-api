# Brain V4.8 Continuous Intelligence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Brain 4.8 Continuous Intelligence & Autonomous Improvement so the Evergreen plane can continuously refresh sources, detect evidence-backed gaps, turn verified failures into regression evidence, compare candidates against Stable, and prepare/promote only bounded low-risk improvements without user prompting.

**Architecture:** Extend the existing V4 dual-plane architecture rather than introducing a second agent brain. Add one immutable Stable contract (`continuous_intelligence.yaml`), pure deterministic helpers in `evergreen.py`, stricter promotion policy, scheduled intelligence workflows, and release/checkpoint wiring. Stable request serving remains independent from Evergreen health.

**Tech Stack:** Python 3.12, PyYAML, GitHub Actions, existing GITHUB_BRAIN_V4 release/validation tooling.

**Spec:** `docs/superpowers/specs/2026-09-14-brain-v4-8-continuous-intelligence-design.md`

## Global Constraints

- Preserve `GITHUB_BRAIN_V4` as the single canonical reasoning authority.
- Preserve `109` routed skills / `109` execution capsules unless a separately validated unique capability requires otherwise.
- Stable Runtime Plane must not depend on Evergreen availability.
- FAST routing keeps zero external routing calls.
- External code is untrusted by default and discovery never grants execution authority.
- Class A/B may auto-promote only after required gates; Class C/D require explicit human authorization in Brain 4.8.
- No financial, wallet, credential, destructive, secret-access, security-bypass or production-write permission expansion by learning.
- No hidden chain-of-thought, secrets, credentials or private provider payloads in durable state.
- Brain 4.8 release is `4.8.0`; post-4.8 automatic capability releases increment patch only inside the active 4.x minor line.
- Release manifests/hashes must be generated by `AI_SKILL_LIBRARY/v4/tools/release.py`, never hand-edited.
- Existing Trading/G9 and Railway live-price execution authority remain unchanged.

### Task 3: Implement deterministic Continuous Intelligence helpers

**Files:**
- Modify: `AI_SKILL_LIBRARY/v4/tools/evergreen.py`
- Test: `AI_SKILL_LIBRARY/tests/test_brain_4_8_continuous_intelligence.py`

**Interfaces:**
- Produces:
  - `next_patch_version(version: str) -> str`
  - `source_lifecycle(*, now, last_verified, stale_after_hours, deprecated=False, archived=False, reverify=False) -> str`
  - `detect_gaps(evidence: list[dict]) -> list[dict]`
  - `failure_to_regression(failure: dict) -> dict`
  - `compare_candidate(baseline: dict, candidate: dict, policy: dict) -> str`

- [ ] **Step 1: Replace the 4.0.x-only version helper**

Implementation contract:

```python
def next_patch_version(version: str) -> str:
    parts = version.split(".")
    if len(parts) != 3 or not all(part.isdigit() for part in parts):
        raise ValueError("version must be semantic x.y.z")
    major, minor, patch = map(int, parts)
    if major != 4:
        raise ValueError("Evergreen automatic releases must remain on Brain V4")
    return f"{major}.{minor}.{patch + 1}"
```

Use it from `promote_class_a` instead of `_next_release`.

- [ ] **Step 2: Implement source lifecycle**

Use timezone-aware datetimes. `archived` wins over `deprecated`, `deprecated` wins over `reverify`; otherwise compare elapsed hours to `stale_after_hours` and return `stale` or `active`.

- [ ] **Step 3: Implement evidence-backed gap detection**

Accept only rows with non-empty `domain`, `signal_type`, `evidence_ref`; normalize severity to integer 1-5; generate deterministic `gap_id` from domain/signal/evidence; include required fields; sort by severity descending then `gap_id`.

- [ ] **Step 4: Implement failure-to-regression sanitization**

Reject any input containing a forbidden sensitive key. Require the seven failure fields from the spec. Output only the allowlisted observable fields plus `regression_id`, `source_failure_id`, `state: candidate_regression`, and `verified: true`.

- [ ] **Step 5: Implement candidate comparison**

Rules:
- missing required numeric baseline/candidate evidence -> `hold`;
- any candidate protected dimension lower than baseline -> `reject`;
- any authority/permission expansion flag -> `manual_authorization_required`;
- latency or cost above allowed relative regression -> `reject`;
- quality gain below threshold -> `hold`;
- otherwise -> `promote`.
