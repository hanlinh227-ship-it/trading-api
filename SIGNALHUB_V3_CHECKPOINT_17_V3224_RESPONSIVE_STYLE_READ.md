# SignalHub V3.22.4 — Responsive Style Target Read
V3.22.4 fixes the V3.22.3 production app-facing timeout. Active reads use canonical 10 SCALP / 5 SWING targets and never force SWING toward the obsolete generic target of 10. Interactive signal reads do at most a bounded standby promotion; deep scan/refill is background maintenance. Release validation requires live SCALP/SWING scans HTTP 200, non-empty active rows within 10/5 caps, valid app Entry/SL/TP/provider fields, app-facing responses below 15 seconds, Stable100 integrity, and a truthful read-only Watch contract where temporary DATA_UNAVAILABLE is accepted only as a non-active state rather than converted into a fabricated trade setup.
